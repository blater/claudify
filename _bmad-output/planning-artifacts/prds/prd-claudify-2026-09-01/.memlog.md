- (decision) Create a browser-based parody translator that rewrites pasted source text or text obtained from a URL into exaggerated Claude-style AI prose.
- (decision) Use deterministic dictionary and semantic-style transformations rather than a server-hosted generative model.
- (decision) Transformation style must heavily favor Claude cliches, hedging, abstraction, marketing verbs, indirect constructions, em dashes, bold text, vertical inline-header lists, occasional decorative emoji, and parallel not/but/however constructions.
- (decision) Output signs of AI writing must be grammatically integrated with source meaning rather than injected as unrelated canned sentences.
- (decision) Ship as a browser-only JavaScript or TypeScript application with no server component and no runtime dependencies.
- (event) User supplied load-bearing and Wikipedia Signs of AI writing pages plus the load-bearing GitHub repository as discovery inputs.
- (decision) Primary audience spans LinkedIn users and Hacker News readers; the parody must be recognizable to mainstream professional-social users and technically self-aware audiences.
- (decision) Treat Claudify as a low-stakes one-off public gimmick, prioritizing immediate comedic impact and minimal maintenance over extensibility or long-term product depth.
- (decision) Use the PRD Fast path: batch remaining gaps, draft a lean full PRD, and mark inferred requirements with ASSUMPTION tags for review.
- (event) User identified the owned /Users/blater/src/liff dictionary codebase as an additional discovery input that may provide reusable data structures or transformation logic.
- (event) Research found load-bearing is MIT-licensed and provides a static ~1,000-word ranked lexicon plus optional browser-side unigram scoring, but not synonym, grammar, syntax, or phrase transformation.
- (event) Liff's authoritative-JSON to generated immutable-TypeScript architecture is reusable, but its dictionary schema, fuzzy token lookup, and punctuation-stripping normalization do not directly fit a grammar-preserving translator.
- (event) Comparable parody translators validate a paste-transform-copy flow, an intensity metaphor, faux social-post presentation, and a visible transformation score or sign tally.
- (assumption) Arbitrary URL retrieval cannot be guaranteed in a dependency-free browser-only app; make paste first-class and URL loading best-effort with a clear paste fallback unless the user expands architecture scope.
- (decision) Provide both rendered rich-text output suitable for LinkedIn-style use and Markdown output suitable for Hacker News or editors, with dedicated copy controls.
- (decision) A convincing transformation requires multiple coordinated rewrite classes beyond keyword replacement, including phrase-level semantic mappings, grammar-gated sentence rewrites, clause and list restructuring, derived stylistic expansion, and formatting.
- (decision) Keep product capabilities and acceptance criteria in the PRD while capturing the deterministic transformation-engine design in the technical addendum.
- (event) Drafted the lean Claudify PRD with eight functional requirements, four success metrics, two counter-metrics, explicit non-goals, and seven indexed assumptions.
- (event) Created a technical addendum defining a seven-pass deterministic transformation pipeline, structured intermediate document, applied-rule ledger, dual serializers, URL adapter limits, rule-data strategy, and fixture-based verification.
- (assumption) The primary flow is a single anonymous visit with no saved state.
- (assumption) Four transformation classes is the minimum recognizable density for suitable inputs of at least 100 words.
- (assumption) A single maximal Claudify action is better scoped than an intensity slider.
- (assumption) A faux-LinkedIn Rich Output preview is part of the MVP joke.
- (assumption) Support inputs up to 10000 characters with a 200 ms transformation target on a current mid-range desktop browser.
- (assumption) Support current stable Chrome, Firefox, Safari, and Edge.
- (assumption) Use a five-person target-audience qualitative smoke test for parody recognition.

- (decision) Absolute semantic integrity is not required for the one-off gimmick; protect concrete payload and apply conservative guards, but accept changes to nuance, emphasis, certainty, or rhetorical force as part of the parody.
- (decision) Treat recognizable distortion of nuance, emphasis, certainty, and rhetorical force as a positive source of humor; preserve source recognizability and coherence, while rejecting over-distorted output that feels weird rather than funny.
- (decision) Claudify output should generally be substantially less clear than Source Text and may be slightly ungrammatical; any output that becomes clearer is a failure, while complete loss of source recognizability remains undesirable.
- (decision) V1 must produce deliberate obscurity entirely through curated phrase maps, narrow deterministic token patterns, authored templates, document restructuring, and density budgets; it will not use NLP parsing, embeddings, a clarity model, or runtime semantic judgment.
